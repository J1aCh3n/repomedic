## Case 005 failure

The Coder changed the interval comparisons from inclusive to strict and the
public suite passed. The Reviewer nevertheless returned `revise` because it
wanted an additional reverse-adjacency test. Tests are forbidden Agent edit
targets, and the reverse-adjacency behavior already exists in the hidden
evaluator. The next Coder response proposed an edit whose old and new text were
identical. Pydantic rejected it, but the exception escaped the graph, leaving
the checkpoint incorrectly marked `running` instead of a terminal
`model_error`.

A diagnostic evaluator run after the workflow failure passed 2/2 hidden tests.
It is evidence about the candidate patch, not a verified workflow result, so
the case remains failed.

## Case 008 failure

The Investigator consumed the maximum 12 read/search operations. Its report
listed five relevant files, so each Coder pass required five reads plus a
proposal preview. The first implementation passed 6/6 public tests. The
Reviewer then requested tests for failure paths even though tests are forbidden
edit targets. During the second Coder pass, the graph reached the 24-call limit
before proposal preview and terminated with `tool_error`.

The manifest allows two repair iterations, but its 24-call budget cannot fund
this observed investigation plus two complete Coder passes. The saved usage
also undercounts the failed pass because local counters are persisted only when
the node returns successfully.

A diagnostic evaluator run after termination passed 2/3 hidden tests. The only
failure was a regex expecting the word `unknown`; the implementation raised
`ValueError("task does not exist")`. The manifest requires `ValueError` and no
side effect but does not require that message, so this hidden assertion is more
specific than the declared contract.

## Interpretation and next protocol revision

The expanded fixture exposed failures that the four-case result did not:

1. Reviewer feedback can demand edits outside the manifest allowlist.
2. Application-level Pydantic validation errors raised inside structured parsing
   are not consistently converted to terminal `model_error` state.
3. Failed nodes lose model usage and tool-call increments.
4. Tool budgets are not checked against the worst permitted repair path.
5. One hidden assertion exceeds its manifest's behavioral contract.

These results should remain immutable. Fixes should increment the prompt and
protocol version before a separate rerun; they must not be presented as part of
this v1 measurement.
